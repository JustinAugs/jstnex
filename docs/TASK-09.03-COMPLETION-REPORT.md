## 09.03.2 发布一致性与限制

两份普通文件不能同时原子替换，因此没有声称多文件硬件原子事务。published.json中的snapshotPath是完整不可变快照的指针；data/observations.json是兼容镜像。发布按独占锁→验证旧/新数据→备份旧快照→持久事务日志→替换镜像→替换指针→再验证→清除日志完成。

正常异常会自动恢复旧镜像与指针；进程硬中断留下事务日志时，校验/构建拒绝通过，显式recover恢复旧版本。后续UI应从指针指向的同一不可变快照读取，不在更新过程中独立拼接两个文件。当前尚无UI读取此层。

build脚本增加validate:data前置，validate:data调用Python原始→发布核对，发现未完成事务/锁、坏hash、观测被改值或镜像/指针不符时失败。维护及构建环境现在需要Python3（建议3.10+）和既有Node22.18+；不新增第三方依赖。

并发写操作通过独占锁拒绝。锁记录pid和开始时间；进程硬杀后可能有残留锁，先确认原进程已停止，再清理该锁并recover，绝不能盲删活动锁。测试覆盖进程/写入故障和恢复；不宣称通过硬盘损坏、断电或跨文件系统持久性认证。损坏的事务日志/原始数据应停止并查因，不能重算hash掩盖修改。

## 09.03.3 操作

所有命令在仓库根目录并确保Node在PATH：

- prepare --batch <已归档batchId> --checked-at <实际核对日期>：生成候选与diff。未来日期/无效日历拒绝，不用重放时间冒充新取源。
- publish --candidate <仓库curated目录内的候选路径>：验证相对基线，基线变更则拒绝；历史值修订需另加--accept-revisions。此选项是明确确认，不替代逐项原表审阅。
- verify：检查当前观测、原始字节、回执及指针快照；无网络。
- restore --candidate <已验证的历史快照或backup目录>：受同样来源/原始/结构校验约束，不绕过合法性门槛。
- recover：在确认无旧进程/残留锁后恢复未完成事务的旧快照。

上述action均通过 `python3 scripts/normalize-wdi.py <action> ...` 运行。旧批次不可改写；源定义/单位变更先复核，不自动接受。候选差异报告仅帮助审核，真实发布仍重新对照raw。
